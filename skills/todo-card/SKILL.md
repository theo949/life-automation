# Todo Card: review a single card (Life Automation)

The `todo-review` skill, narrowed to one card: the one the user has open in Trello, or the one they name. Same rules, same card-level steps, no board walkthrough. In this skill "the user" is the person running the review. Write to them as "you".

## Start
1. Load the `todo-review` skill with the Skill tool and read it, and load its helper skills `todo-review-rules`, `todo-review-actions` and `todo-review-scan` in the same batch (all four at once); `todo-review-meetings` is loaded when a meeting is created, moved, removed or found stale. Everything `todo-review` and `todo-review-rules` say about loading settings, learnings, Showing text, Choices, Card metadata format, Deadlines, Stated done is the go-ahead, The card menu, Snoozing (including the fast paths, buckets, "Every snooze wakes on a reply", "The snooze date" and "Clear snooze"), the Comments rule, Step 3.2 and Step 3.3 (the typed check-in) applies here unchanged, and so does everything `todo-review-meetings` says about Meetings and travel and Meeting cleanup, and everything `todo-review-actions` says about Past meetings, Cleanup check, Card content check, Emails, After an email was sent, Write at once, Step 2c and Step 4, and everything `todo-review-scan` says about Linked Google files, Step 1a and Step 1b. Where this skill and that one differ, this one wins for scope.
2. Follow **Before anything else: load settings** from `todo-review` (memory file `/areas/life-automation.md`). If the settings are missing or have no board name, stop with the same one-line message pointing to `/todo setup`.
3. Read the learnings file `/areas/life-automation-learnings.md` (memory_read) and follow it.

## Find the card
- If the user names or links a card in chat, use that card.
- Otherwise look at the browser they are working in (Claude in Chrome tabs context, or the built-in browser). The active tab on a Trello card has a URL like `trello.com/c/<shortLink>/...`. Read that card with the Trello connector (description, checklists, comments, members, labels, due date, current list).
- If no browser is reachable (for example a cloud or scheduled run) or the active tab is not a card, ask for the card name or link. If they give a name, use trelloSearch on the Life Automation board. If there are several plausible matches, show the top ones as a typed numbered menu (see **Choices** in `todo-review`). Never guess.
- Name the card in the first line of the summary so a wrong match is easy to catch.
- **Where the card sits:**
  - In one of the three Snoozed lists (`Snoozed/Waiting this week`, `Snoozed/Waiting next week`, `Snoozed/Waiting later`): say so and ask, typed (`1 Yes, wake it · 2 No, leave it snoozed`), whether to wake it before reviewing.
  - A `Snoozed until` line in the metadata but the card sits in a regular list (the user moved it themselves): treat it as woken, clear the snooze lines the next time you update the metadata, and mention it in the summary.
  - In `Proposed`: it is a suggestion, not a task yet. Handle it with the Step 2c options from `todo-review-actions` for this one card (Add, Merge, Dismiss, Already completed), then stop. Do not run the rest of the review on it.
  - In `Done`: say so and ask, typed (`1 Yes, bring it back to In Progress · 2 No`), whether to bring it back before reviewing.
  - On a different board than the saved one: say so and ask before going on, typed (`1 Yes, go on · 2 No`).

## Scope: what to skip
- No board-wide reads, no Step 0 ordering, no brief, no card pack, no waking or rolling forward other cards, no proposal triage for other cards, no "X/N" numbering, no moving on to a next card.
- The Review prep and Card cache tabs are not needed: prep this one card live. The Card news tab is still used first, as in Step 1a.
- The 3-cards-per-day enrichment cap does not apply: the user asked for this card, so enrich it if it has no metadata.
- Meeting cleanup covers only this card's `Events:` list.
- Do not write the Card cache tab. A card that changed is simply written fresh in the next full review.

## Run
1. **Gather for this card only.**
   - Card has metadata: Step 1a (new emails and calendar events involving the listed people since `Last updated`; re-check listed meetings against Google Calendar, and check each upcoming in-person meeting for a missing travel event, see Meetings and travel item 8).
   - Card has no metadata: Step 1b (30-day window around creation). Queue the metadata found and say what was added in the summary; don't ask for confirmation first.
   - Card has a linked Google Sheets, Docs or Slides file (either case): run the **Linked Google files** check (comments read with the comments option on, changed statuses, new since `Last updated`). Show new comments or status changes as the first bullet of the summary, and put what to do about them in the suggested action.
   - Always (either case): run the **Card content check** (checklists read directly; checklist items, title and description against comments, emails, calendar and activity) and the **Past meetings** follow-up check for this card's listed meetings from the last 14 days whose outcome isn't recorded, and the **Cleanup check** (anything on the card that is no longer needed). If either found something, the reply that shows the summary ends with that typed question instead of the menu, and the regular menu follows after the answer, as in `todo-review`. Show findings as bullets in the summary and put the update in the suggested action. If the user says something is done, apply **Stated done is the go-ahead** and tick the matching checklist item.
2. **Stale meetings:** if any, write ONE closing reply, typed, as in Step 2a of `todo-review-meetings`: the list of them, the question `Remove N stale meetings?` and `1 Yes, remove them · 2 Keep them for now`. Never remove silently.
3. **Summary:** do not send it yet: build it together with the menu in step 4 and write both as ONE closing reply of the turn, in plain chat text. **Never send it with SendUserMessage, and never both: the card text exists exactly once.** The summary is: `**[name](link)** · list · due <Mon D> if any`, then 1-2 bullets on where it stands (latest comment, new emails with thread links, what it's waiting on, money or dates, the user's own next step). Only still-future meetings are shown as upcoming. If an upcoming in-person meeting has no travel event, add one bullet for it. If a helper added the `Health` label to the card today (a comment `Health label added automatically` with today's date), add the bullet `Added the Health label, since this looks like a medical card.`, as in Step 3.1 of `todo-review`. If the card has an outside deadline, a bullet says what happened to it, as in Step 3.1 of `todo-review` (a missing due date is set by the review and the bullet says so). Every bullet that mentions an email, a meeting or a file ends with its `[email]`, `[event]` or `[doc]` link (see **Links in bullets**). The LAST bullet is the **Recommendation bullet** of Step 3.1 (`Recommended: <option 1 with its date> because <reason>.`, plus the wake clause when option 1 is a snooze). Times are in 12-hour form with AM/PM.
4. **End the same reply with the typed menu** from the todo-review skill's **The card menu** and Step 3.2: ① the work (at most 8 words), ② Snooze 7d (date), ③ Snooze 30d (date), ④ Skip, with the deadline rules applied (including that a fixed-date deadline gets no `Due date to` pick). The options are numbered 1, 2, 3 in a row with Skip always last: an option that cannot be shown is left out and the others close up, and the prompt line shows the real count. Skip is always called Skip. The numbers are the circled digits ①, ②, ③, ④ (one character each, see **The numbers** in `todo-review`). When the only thing still open on the card is an upcoming meeting, slot 1 is the snooze to the meeting: `Snooze <N>d (<Mon D>, meeting day)` if the meeting is tomorrow or later, `Snooze <N>d (<Mon D>, after the meeting)` if it is today. `Snooze 30d` is never shown while a meeting is on the card, and no snooze comes back after the meeting day (see Step 3.2). The user answers by typing a number or their own words. No AskUserQuestion here. After one blank line add the fixed prompt line from **The card menu** (`Type 1–<N>, or just tell me what you have in mind.` with the real count). Because this reply is the closing reply of the turn, nothing can follow it: no recap, no copy of the card or of the prompt line. Any tool calls for this turn go in ONE parallel batch before it (no acknowledgement line, no timestamp call, no read the card does not need).
5. **Act** as in Step 3.3, Step 3.4 and Step 4 (with the menu slots in place of the old buttons, and every snooze waking on a reply; a move to Done follows **Meetings when a card goes to Done** in `todo-review-rules`): Trello comment only under the **Comments rule** in `todo-review` (no comment for a plain snooze, and a mark done comment only when the user gave a reason), metadata update, list moves (a snooze goes to the right Snoozed list for its date, see Snoozing and its fast path), snooze only with a date the user chose, emails shown in full (with the Life Automation footer from Step 4) and sent only after the user's yes, using the typed send question from **Emails** in `todo-review-actions` (the draft and the menu `Send it · Hold off` in one closing reply). Any meeting created follows Meetings and travel. Every Trello card write (a snooze, a mark done, comments, metadata, checklist ticks, list moves, due dates) is queued, not written now (see **Write queue** in `todo-review`): nothing is announced (no recap and no `Queued:` bullet; see Step 3.5 in `todo-review`), and they are written once, in one background step, at the wrap-up. Emails and calendar events are done at once, and the one exception to the queue applies: when an email was sent or a calendar event was created, the card's dated comment and metadata for it are written right away, in that same turn (see **Write queue**). **Website sign-in:** follow Step 4 of `todo-review-actions` (request the login from the password manager BEFORE opening the page, use Claude in Chrome, autofill, release; never type a password or create an account; if it cannot be done, ask the user to sign in and go on after they confirm). **A clear snooze or a clear mark done typed by the user** (for example `snooze 3 days`) ends the card at once, with no check-in, exactly as in **Clear snooze** in `todo-review`: use the number exactly (3 days is today plus 3 days, never moved to another day), queue it and go to the wrap-up. The same goes for a snooze or mark done typed together with other work (`send the email and snooze 7 days`): do the work, queue the snooze, no check-in. A typed `snooze` with no length uses the recommended snooze, and a length past the deadline or the next meeting uses the latest allowed date with a one-line note (**The snooze date** in `todo-review-rules`).
6. **Check-in loop:** after any action, or whenever the user typed anything themselves, except a clear snooze or a clear mark done, write ONE closing reply (plain chat text, never SendUserMessage, so the text exists exactly once) built exactly as in Step 3.3 of `todo-review`: any note (Step 3.5 in `todo-review`), then the **Recommendation bullet** as the last bullet (`Recommended: <option 1 of the check-in line, with its date> because <reason>.`, as in Step 3.1 of `todo-review`), a blank line, the typed check-in line with circled numbers, a blank line and the prompt line. It is typed (see **Choices**), with no question sentence above the options and no descriptions under them. Tool calls for the turn go before it, in ONE parallel batch. The check-in line is the card menu without the work option, numbered from 1 with no gaps and with Skip always last: `Mark it done 🎉` first (only when the work looks finished: nothing left open, no unchecked checklist items, no reply being waited on, or when the evidence shows the task is already done, such as a payment receipt: then say so in the Recommendation bullet and recommend it), then the two snoozes (`Snooze 7d (<Mon D>)` and `Snooze 30d (<Mon D>)`, or the deadline labels of Step 3.2 for a card with a deadline in the next 31 days), then `Skip`. When we just sent an email or request, the options are the date options of **The snooze date** in `todo-review` (`Snooze 7d · Snooze 3d · Snooze 14d · Skip`, with no "Mark it done 🎉"), in this same reply. When the only thing still open on the card is an upcoming meeting, follow the meeting rules of Step 3.3 in `todo-review` (the snooze to the meeting day, or to the next working day after it when the meeting is today; no `Snooze 30d` while a meeting is on the card; no "Mark it done 🎉"). The prompt line is exactly `Type 1–<N>, or just tell me what you have in mind.` with the real count. If no snooze fits, use the line `Mark it done 🎉 · Skip (stays in <list>)` from Step 3.3 of `todo-review` instead of a bare sentence (never `wakes on reply`: nothing is snoozed).
   - Never label an option plain "Done" or "Finish" unless choosing it moves the card to `Done`.
   - Reading the reply: "Mark it done 🎉" follows the **Mark done fast path** (checklist check first, and if items are unchecked warn and ask before moving it). A snooze follows **Snoozing**, and the card is then finished. Skip ends the review of the card and goes to the wrap-up. A reply that contains `#offline` queues the rest of the text as an offline job: load `todo-offline` (once), follow **Queueing a job** there, and show the check-in again. Anything else the user types is their next instruction on this card: do it, update the card, and show the check-in again.
   - Keep going until the user picks one of the finishing options. Never end by yourself after something the user typed.
7. **Wrap-up:** the wrap-up message goes first and alone (SendUserMessage, no other tool call in that turn). The wrap-up uses the same layout as the full review (Step 5 in `todo-review`): one line per item with its icon and a blank line between lines, only the lines that apply: `✅ Done: <what changed in the real world and on the card, never bookkeeping>`, `📨 Sending: <email to Name>, right now. Please keep this window open until it says sent.` per queued email, and ONE `🔄 Trello: tidying up now (<the queued changes, one short clause each>)` line when anything was queued (never `N card changes are being applied`). Propose 0-2 learnings from this session before it, while the card is still on screen, and save only the ones the user confirms, as in **Learnings** (the learning itself in the reply, then the typed question `1 Remember it · 2 Skip`). The last line of the wrap-up message is `🎉 Done and dusted! Trello is updating itself. Catch you tomorrow, or sooner.` when anything was queued. No "focus for tomorrow" list. Right after it, in one parallel batch, start one email step per queued email (see **Emails** in `todo-review-actions`) and the flush of the queue in the background (see **Write queue**; the flush leaves out the cards that have an email step). When an offline job is queued, the wrap-up message also has the line `🌙 Offline: <the job, one short clause>, once we're done here`, and the one scheduled task from `todo-offline` is started as soon as the flush report is in. Then send the **closing message** from **Write queue** (`✅ All saved. Trello is fresh and up to date.` or the failed state), sent only after the flush report is in. The closing message also says `📨 Sent: email to <Name>, on its way!` or `Not sent: <Name> (<reason>)`. Never tell the user to keep the window open, except in the `📨 Sending` line while an email is being sent.

## Unattended runs
If nobody is there to answer, change nothing on the card. Report what you found (new emails, stale meetings, a suggested next step) so the user sees it next time.
